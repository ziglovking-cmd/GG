# amoCRM — следующий шаг

Кода интеграции раньше не было. Сейчас есть `bot/amocrm.py`: он **ничего не шлёт**, пока в окружении сервера пустые `AMOCRM_BASE_URL` и `AMOCRM_TOKEN`. Ключи в репозиторий и в архив Windows не кладём.

Поле «Telegram уведомление» не нужно. Это исходящее уведомление, не история чата. Гостя ищем по телефону или по Telegram id на контакте.

## Что сделать в amo

1. Откройте `https://odinmaltseva.amocrm.ru` → **Настройки → Интеграции → Создать интеграцию**.
2. Права: контакты, сделки, беседы (если чаты уже приходят через виджет — текст может жить там, бот его не дублирует сам).
3. Возьмите **долгоживущий токен** на вкладке «Ключи».
4. На сервере, только в `.env` (не в git):

```env
AMOCRM_BASE_URL=https://odinmaltseva.amocrm.ru
AMOCRM_[REDACTED]
AMOCRM_FIELD_DATES=
AMOCRM_FIELD_GUESTS=
AMOCRM_FIELD_DISTRICT=
AMOCRM_FIELD_OPTION=
AMOCRM_FIELD_TELEGRAM=
```

`AMOCRM_FIELD_*` — числовые id дополнительных полей. Пока id пустой, это поле не отправляется.

## Когда бот должен писать в amo

Функция `plan_action` в `bot/amocrm.py`:

| Момент | Сделки ещё нет | Сделка уже есть |
|---|---|---|
| Гость назвал даты и число гостей | создать сделку | обновить даты и гостей |
| Гость выбрал вариант | создать, если пропустили прошлый шаг | дописать название квартиры |
| Передача менеджеру | создать с тем, что уже известно | примечание, без второй сделки |

Вызов из живого ответа ещё не подключён, чтобы пустой токен не трогал Telegram и amo. Следующий коммит: после того как токен лежит на сервере, вызвать `maybe_sync` в этих трёх местах и проверить чтение одной сделки. Ошибку amo ответ гостю не должен ронять — `maybe_sync` это уже глушит.

Проверка без сети: `python tests/test_amocrm.py`.
