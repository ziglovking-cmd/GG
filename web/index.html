Источники

В супергруппе список участников доступен обычному участнику — если владелец не включил «Скрывать участников». В канале-вещалке подписчиков видит только админ; при отсутствии прав парсер сам переключится на историю сообщений.

Перед инвайтингом парсите всеми аккаунтами. Каждый получит свои access_hash, без которых он сможет приглашать только юзеров с @username. Аккаунты идут по очереди с паузой, все должны состоять в чате.

Длинные чаты. На паузы Telegram (FloodWait) и обрывы связи парсер ждёт и продолжает с того же сообщения. Если Telegram просит ждать дольше 15 минут или задачу остановили — место сохраняется: запустите тот же чат тем же аккаунтом, и проход продолжится.

Единая база чата. Каждый проход дополняет накопленную таблицу. Пользователи с уже известным Telegram ID не добавляются повторно и не увеличивают счётчик «новых за проход». Общий размер базы показывается отдельно. Для продолжения парсинга не удаляйте чат из вкладки «База».

Задачи

Загрузить свою CSV-базу

Поддерживаются CSV с разделителем ;, , или табуляцией. Нужен столбец user_id или username. Максимум 10 МБ и 100 000 строк.

Файл не выбран

CSV не переносит access_hash: пользователей без @username можно хранить в базе, но для приглашения аккаунт должен самостоятельно увидеть их в Telegram. Загружайте только данные, которые вы вправе обрабатывать.

Режим уведомлений

Бот отправляет подробный статус после каждой фактической попытки приглашения, которая запускает интервал аккаунта. Фиксированного расписания по часам нет. Настройки приватности пропускаются сразу и отдельное уведомление не создают.

Журнал

API Telegram

Получите на my.telegram.org → API development tools. Одна пара api_id/api_hash используется всеми аккаунтами. Хранится локально в data/config.json.

Как это работает

  • Парсинг идёт с обычного аккаунта через MTProto: список участников, авторы сообщений и те, кто ставил реакции.
  • access_hash у каждого пользователя свой для каждого вашего аккаунта. Поэтому заведите все инвайтеры в чат-донор и спарсите его каждым из них — иначе доступны будут только юзеры с @username.
  • Интервал задаётся отдельно для каждого аккаунта в секундах. Можно указать диапазон, например 90–240, или точное значение 14400–14400.
  • Приватность: пользователь сразу пропускается, не учитывается в суточном лимите и не запускает ожидание до следующей цели.
  • PEER_FLOOD выводит аккаунт из ротации на сутки автоматически. Если он повторяется — аккаунт в спамблоке, лимиты надо снижать.
  • USER_PRIVACY_RESTRICTED — у пользователя стоит «добавлять меня могут только контакты». Это не ошибка и не лечится, таких примерно 70%.
