## 1. Как провести видеоконсультацию (вы ведёте)

### До созвона

1. Вышлите заказчику `TZ_CONCLUSION.md` за сутки (без session/proxy/ключей).
2. Попросите подтвердить: можно ли шарить экран с **обезличенным** кодом и логами.
3. Зафиксируйте в письме: «секреты, `.session`, прокси, api_hash, токены на созвон не нужны и не принимаются».
4. Заготовьте 4 закладки: `attempts.py`, `verification.py`, `failures.py`, `db.py` (busy_timeout / claim).

### Тайминг 75 минут (говорите вы)

| Мин | Блок | Ваш текст / действие |
|---|---|---|
| 0–8 | Рамка | «Разберём причины, не обход лимитов Telegram. Успех = человек в чате, не RPC OK.» |
| 8–20 | Старые vs новые | Экран / схема: свой `access_hash`, `@username`, тихие потери. «У id3 ~16k hash, у новых 30–100 — это главная разница резолва peer.» |
| 20–40 | Очередь | Live-walk: claim → arm marker → Invite RPC → 5× presence → finalize. Таблица статусов из заключения. |
| 40–50 | Ошибки | missing_invitees / privacy / silent loss / PEER_FLOOD / tech. «Суточный лимит жжёт только confirmed.» |
| 50–60 | SQLite | Показать busy_timeout + IMMEDIATE claim/arm. «database is locked — инфраструктура, не Flood.» |
| 60–70 | Демо приёмки | `pytest` зелёный; 1–2 теста unconfirmed / locked. |
| 70–75 | Смета | Пакеты A/B/C, что уже сделано, что опционально, критерии приёмки, счёт. |

### Фразы, которые стоит сказать прямо

- «Silent loss — ответ API: RPC принят, участника нет. Это не баг счётчика.»
- «Чужой access_hash использовать нельзя — будет PEER_ID_INVALID / хуже.»
- «После реального Invite защитный интервал оставляем: лимиты не обходим.»
- «Техсбой до маркера — сразу retry; после маркера — только проверка членства, без второго Invite.»

### После созвона (в течение 24 ч)

Письмо заказчику:

1. Краткое резюме (5–7 пунктов)
2. Ссылка на `TZ_CONCLUSION.md` (+ правки, если на созвоне что-то уточнили)
3. Перечень изменений в коде (уже в PR) + diff
4. Счёт / оффер по пакетам ниже
5. Критерии приёмки и срок гарантии на пакет B (например 14 дней багфиксов по этим пунктам)

## 2. Оценка стоимости — как назвать заказчику

Ориентир ставки специалиста: **5 000 – 7 000 ₽/час**.

### Как выставить счёт сейчас (рекомендация)

**Вариант 1 — честный и сильный:**  
`A + B` = **175 000 ₽** (консультация + уже сделанное внедрение и приёмка).  
Пакет C — отдельным доп. соглашением после 2 недель метрик.

**Вариант 2 — если код отдают «в подарок к ревью»:**  
только **A = 35 000 ₽**, B показывают как уже закрытый риск, C квотируют отдельно.

**Вариант 3 — retainer:**  
B как есть + **40 000 ₽/мес** сопровождение очереди (не более N часов).

### Текст оффера в один абзац

> По итогам ревью: разница старых/новых аккаунтов — в per-account `access_hash` и в «тихих» отказах API; суточный лимит нельзя крутить от неподтверждённого RPC; SQLite нужен busy_timeout и атомарный claim.  
> Стоимость: пакет A (консультация) — **35 000 ₽**; пакет B (внедрение по ТЗ) — **140 000 ₽**, код готов к приёмке в PR; пакет C (warmup и метрики) — **180 000 ₽** по отдельному согласованию.  
> Приёмка B: pytest зелёный; `successful_today` только после confirmed; unconfirmed/privacy/tech не жгут дневную квоту; нет стабильных `database is locked` под параллельным reporter.

### Критерии приёмки (проговорите в конце созвона)

1. Успех только при подтверждённом присутствии  
2. Privacy / missing / unconfirmed / tech — раздельные ветки, без ложной «суточной паузы» от tech/unconfirmed квоты  
3. PEER_FLOOD / FloodWait не маскируются под retry  
4. SQLite: busy_timeout ≥ 30 с, claim/arm в IMMEDIATE  
5. Регрессия: pytest ≥ 136 passed
