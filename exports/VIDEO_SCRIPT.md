Здравствуйте. Это сдача работ по ТЗ инвайтинга: ревью очереди Telethon и внедрение правок.

Проблемы, которые вы описали: старые аккаунты доставляют, новые нет; бывают missing_invitees и тихие потери; после неподтверждённого инвайта казалась суточная пауза; плюс database is locked.

Корневые причины. access_hash пользователя действует только для своего аккаунта. У старого их тысячи, у новых — десятки. Кроме того, Telegram может принять Invite RPC без ошибки, но человека в чате не окажется — это ответ API, не баг счётчика.

Правильная очередь. Успех засчитываем только после подтверждения присутствия. Privacy, missing_invitees, тихая потеря и техсбой — разные ветки. Технический сбой не жжёт суточный лимит. Лимиты Telegram не обходим: после реального Invite защитный интервал сохраняется.

В коде: busy_timeout тридцать секунд, атомарный claim цели, IMMEDIATE на маркере Invite RPC, database is locked считаем техническим сбоем. Регрессия — сто тридцать шесть тестов зелёные.

Стоимость: пакет A консультация — тридцать пять тысяч; пакет B внедрение — сто сорок тысяч; вместе сто семьдесят пять. Пакет C с warmup hash — отдельно.
