# Видеоконсультация и оценка стоимости

Документ для проведения созвона со специалистом по ТЗ и для фиксации цены внедрения.

---

## 1. Как провести видеоконсультацию (60–90 мин)

### До созвона (вы готовите, секреты не передаёте)

Отправьте специалисту **только обезличенное**:

1. `exports/TZ_CONCLUSION.md` — выводы
2. `exports/expert_2026-10-28/` — диагностика кампании 26
3. `exports/Журнал Инвайтинг.docx` — фрагмент логов
4. Ссылку на PR / diff без `.session`, прокси, `api_hash`, токенов
5. Одну таблицу пула (без телефонов):  
   `account_id | age_days | hash_count | proxy_shared_yn | invited_ok | silent_loss | peer_flood`

Правило на созвоне: **экраном делитесь только кодом и метриками**, не `data/*.session` и не `config` с ключами.

### Повестка

| Мин | Блок | Что фиксируете |
|---|---|---|
| 0–10 | Контекст | Цель: доставка в чат, не «больше RPC». Метрики: confirmed / missing_invitees / silent_loss / PEER_FLOOD |
| 10–25 | Почему старые ≠ новые | Свой `access_hash`, `@username`, тихие потери API. Согласие: чужой hash не переиспользовать |
| 25–45 | Очередь и исключения | Экран: `attempts.py` → `verification.py` → `failures.py`. Успех только после presence; privacy отдельно; tech без суточной паузы; лимиты TG не обходим |
| 45–60 | SQLite | `busy_timeout`, IMMEDIATE claim/arm, reporter vs core. Критерий: нет `database is locked` под нагрузкой |
| 60–75 | Разбор кейса | Кампания 26: id 3 vs id 45 на одном чате. Что считать нормой API, что — багом софта |
| 75–90 | Оценка и next steps | Пакеты A/B/C ниже, критерии приёмки, кто мержит, кто катит на VPS |

### Вопросы, которые стоит задать специалисту

1. Согласен ли, что silent loss — ответ Telegram, а не дыра в счётчиках?
2. Достаточно ли 5 проверок (0/1/3/7/15 с) или нужен длинный отложенный re-check?
3. Нужен ли warmup `access_hash` для новых аккаунтов до старта кампании?
4. Оставляем SQLite+WAL или уже пора Postgres при N воркерах?
5. Что из пакета C он считает лишним / рискованным для ToS?

### Что получить на выходе созвона (письменно в чат/письмо)

- Подтверждение или правки к `TZ_CONCLUSION.md`
- Список «обязательно / желательно / не делать»
- Выбор пакета внедрения и сумма
- Критерии приёмки (см. ниже)

## 2. Оценка стоимости — наименованные пакеты

Ставка ориентир для узкого Telethon/asyncio специалиста (СНГ, 2026):  
**4 000–7 000 ₽/час** или **fixed** ниже.  
Цифры — смета на внедрение/приёмку, не оферта.

### Пакет A — «Консультация» (уже закрывает блок ТЗ про созвон)

| | |
|---|---|
| Состав | Созвон 60–90 мин + письменное заключение + рекомендации + список правок |
| Объём | 3–5 ч |
| **Цена** | **25 000 – 40 000 ₽** |
| Статус у вас | Заключение уже есть (`TZ_CONCLUSION.md`); созвон — сверка с внешним экспертом |

### Пакет B — «Исправления ТЗ» (core fix)

| | |
|---|---|
| Состав | Успех только после presence; раздельные privacy / missing / tech; суточный лимит не от unconfirmed; SQLite busy_timeout + атомарный claim; тесты; выкат |
| Объём | 16–28 ч |
| **Цена** | **90 000 – 160 000 ₽** |
| Статус у вас | **Уже сделано в PR #8** (логика + hardening + 136 тестов). Внешнему специалисту остаётся **code review / приёмка**, не полная разработка с нуля |

### Пакет C — «Усиление эксплуатации» (опционально после B)

| | |
|---|---|
| Состав | Warmup hash для новых аккаунтов; дашборд воронки confirmed/silent/missing; запись сырых Updates по флагу; нагрузочный тест SQLite; runbook PEER_FLOOD |
| Объём | 20–40 ч |
| **Цена** | **120 000 – 250 000 ₽** |
| Статус | Не входит в минимальное ТЗ; брать только если нужна наблюдаемость и меньше ручной диагностики |

### Как назвать в договоре / переписке

1. **«Консультация Telethon / очередь инвайтов»** — пакет A  
2. **«Внедрение исправлений по ТЗ инвайтинга (очередь + SQLite)»** — пакет B  
3. **«Расширенная диагностика и warmup access_hash»** — пакет C  

Рекомендуемая формулировка сейчас:

> Оплата: пакет A (созвон + ревью готового diff).  
> Пакет B считаем выполненным по PR #8; оплата B внешнему подрядчику — только если найдены дефекты приёмки.  
> Пакет C — отдельным ТЗ после 2 недель метрик на проде.

### Критерии приёмки пакета B (чтобы не спорить на созвоне)

1. `successful_today` растёт только при `invite_confirmations.result='confirmed'`
2. Unconfirmed / privacy / missing_invitees не увеличивают суточный лимит
3. Tech до Invite RPC — requeue без cooldown; после маркера — без повторного Invite
4. Под параллельным reporter нет стабильных `database is locked`
5. Регрессия: `pytest` зелёный (≥136)
