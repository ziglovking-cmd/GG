# Отчёт по ТЗ инвайтинга (кратко, по всем пунктам)

## Что было не так

1. **Старые аккаунты работают, новые — хуже.**  
   `access_hash` пользователя свой у каждого аккаунта. У старого их тысячи, у новых — десятки. Чужой хэш нельзя подставлять. Без своего hash и без `@username` новый аккаунт цель не пригласит.

2. **`missing_invitees` и «тихие потери».**  
   Telegram иногда явно отказывает (`missing_invitees`), а иногда принимает Invite RPC без ошибки, но человека в чате нет. Это ответ API, не баг счётчика.

3. **После неподтверждённого инвайта казалась «суточная пауза».**  
   Суточный лимит должен расти только от реального добавления в чат, а не от факта отправки запроса.

4. **`database is locked`.**  
   Параллельная запись (воркеры + reporter) без нормального ожидания блокировок SQLite.

## Логика очереди сейчас

- **Успех** → только если человек реально в чате.  
- **Тихая потеря** → `failed`, квота **не** растёт, защитный интервал после RPC **остаётся**.  
- **missing_invitees** → отказ, интервал освобождается.  
- **Privacy** → отдельно, без дневного cooldown.  
- **Tech до Invite** → цель снова в очередь, без паузы.  
- **Обрыв после маркера** → без второго Invite, только проверка членства.  
- **PEER_FLOOD / FloodWait** → ограничения Telegram, не маскируем под retry.

## Что изменено в коде

3. `telegram.py` — `database is locked` = техсбой, не лимит Telegram.

Ранее в проекте уже было и сохранено: двухфазный invite → verifying → confirm; раздельные privacy/missing/PEER_FLOOD; at-most-once маркер.
