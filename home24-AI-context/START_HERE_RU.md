# Home24 — контекст для новой нейросети

Это компактный, санитизированный пакет для передачи другой модели. Это **не** полный PRIVATE backup.
Собрано: 2026-11-14 01:23:25 Europe/Moscow, **только из уже существующего архива** от 13 ноября 2026 (Europe/Moscow). Живой сервер заново не опрашивался.

## Что это

Home24 — бот и панель для посуточной аренды квартир в Москве и области. Гости пишут в Telegram, бот ведёт диалог по сценарию, показывает свободные варианты (TravelLine + каталог/script), умеет передать разговор менеджеру. Владелец управляет рассылкой и чатами через веб-панель.

## Подтверждённое на момент архива (13.11.2026)

- Действующая сборка кода: **v10.22 · 14.11.2026** (`bot/version.py`, поле `BUILD`; в архиве-источнике было v10.20). Поле `__version__` = 9.5.0 относится к Telethon app_version и **не** является номером сборки.
- **RAG grounding** (`bot/rag.py`): перед запросом к LLM в system prompt попадают только релевантные факты из script.md / FAQ / карты квартир / policy. Отключить: `RAG_OFF=1`. Проверка: `PYTHONPATH=. python scripts/rag_probe.py "какой залог?"`.
- **Идеальный менеджер** (`bot/ideal_manager.py` + эталон в `smart_prompt.txt`): тон живого менеджера по диалогу, который начальница назвала идеальным. Релиз на сервер: `bash scripts/pack_server_release.sh` → см. `code/deploy/README_SERVER.md`.
- Воронка с v10.13: **район → даты → гости** (раньше было даты → гости → район). Старые тесты под прежний порядок могут падать — это ожидаемо, если они не обновлялись.
- Свободные квартиры: для указанного района код v10.18/v10.20 отдаёт все подходящие варианты без искусственного обрезания «топ-3». Фильтр по **вместимости** остаётся: если гостей больше, чем спальных мест, квартира не показывается. Счётчики вида «4 из 6» по вместимости в проверке 12.11.2026 были **правильными**, это не баг.
- Ссылки в карточках квартир в v10.18/v10.20 — на `home24.msk.ru`. В v10.16 в карточки попали guide-ссылки sslip.io; владелец тогда сказал, что так задумано, позже ссылки сайта вернули, путеводители вынесли отдельно.
- Пометки про животных: функция `pets_note()` пишет скобку **только если животных можно**. Если нельзя — отдельной пометки «нельзя» нет. Это текущее поведение кода. Владелец ранее хотел, чтобы в скобках было и «можно», и «нельзя».
- После handoff бот с v10.4 может снова ответить, если менеджер молчит ~15 минут. При рестарте со службами это давало «startup catch-up» по старым сообщениям — поэтому в операциях сначала чистили тестовый диалог, потом стартовали службы.
- Рассылка: рабочие часы в конфигурации 10–20 (часовой пояс Europe/Moscow, если не сказано иное), у аккаунтов есть дневной/недельный лимит (на srv-1 исторически 172/1200, на buy-2 30/1200 — **как было в конфиге на момент архива**, не перепроверялось 14.11). Есть 14-дневный кулдаун повторной рассылки в коде v10.10+.
- Ограничение Telegram **PeerFlood / FloodWait нельзя обходить**, сбрасывать, перевязывать получателя на другой аккаунт или расширять часы ради обхода. Это явное правило владельца и операторов. Исторически buy-2 попадал под PeerFlood; актуальный статус 14.11 с сервера не снимался.
- Тестовый контакт «Ия» использовался для проверочных приветствий; в этом пакете он обезличен (Guest-NN). Скрипт `scripts/reset_contact.py` для точечной очистки не использовали: слишком широкий scope.
- Отправку сообщений из агента не делать; штатная отправка — кнопка панели.

Пометки: «подтверждено кодом/архивом на 13.11.2026». Всё, что могло измениться после этой даты, здесь **не подтверждено**.

## Архитектура (кратко)

- Python-бот (`bot/main.py`, `bot/engine.py`, `bot/smart.py`) + LLM-промпты `bot/smart_prompt.txt`, `bot/edge_prompt.txt`, сценарий `script.md`, RAG `bot/rag.py`.
- Данные: SQLite `home24.db` (контакты, сообщения, слоты сессий, meta). В этот пакет **сырые БД не входят**, только схема и обезличенные текстовые выгрузки.
- Каталог и карта квартир: `script.md`, `bot/apartments_map.py`, `bot/catalog.py`, `data/travelline_rooms.json`.
- Доступность: TravelLine (`bot/travelline.py`).
- Панель: `bot/dashboard/`.
- Аккаунты Telegram, лимиты, антифлуд: `bot/tg_accounts.py`, `bot/rate_limit.py`.
- Дедуп повторных вопросов: `bot/question_dedupe.py` (v10.20).
- Опционально amoCRM, но это не ядро диалога.

## Пожелания владельца (из переписки, без выдумок)

- Ответы должны быть нормальными, без бессмысленных повторов, при этом не ломая уже принятый сценарий.
- Присылать **все свободные** подходящие квартиры, со ссылками; в скобках — можно ли с животными (владелец хотел оба варианта: можно / нельзя).
- Тестовые выкладки новой версии + очистка внутренней истории тестового контакта; рассылку запускает сам владелец кнопкой, не агент.
- Не обходить ограничения Telegram, не слать всем pending сразу, если в очереди чужие номера.
- Для нейросети нужен компактный полезный контекст, а не сырой private backup с паролями.

## Как запускать тесты (изолированно, без живых ключей)

В каталоге `code/`:

```
python -m venv .venv
.venv/bin/pip install -r requirements.txt
cp config/env.example .env   # только плейсхолдеры, без секретов
PYTHONPATH=. .venv/bin/pytest tests/ -q
```

Живые ключи TravelLine/Telegram/Groq подставлять не нужно для большинства офлайн-тестов; если тест лезет в сеть, его следует считать интеграционным и не гонять против продакшена. Старые сценарии в `tests/dialogs_home24.py` могут не совпадать с воронкой «сначала район».

## Известные особенности / баги (не выдумывать новые)

1. **Путеводитель / выбор гида (в т.ч. маршрут вроде Чехова):** в проверках v10.20 тест `test_craft_multi_address_then_name` ожидал сразу ссылку на путеводитель после выбора имени, а бот мог сначала спросить даты. Считать расхождением кода и ожидания теста; не «чинить» вслепую без новой проверки.
2. **Тег животных только положительный:** в карточках есть пометка, если можно с животными; явного «нельзя» код не пишет. Это поведение кода, не обязательно ошибка, но расходится с формулировкой владельца «можно или нет».
3. **Вместимость (4 из 6 и подобные):** в разборе 12.11.2026 отбор по числу гостей работал правильно. Не трактовать меньшее число карточек как «бот скрыл свободные», пока не проверены район и вместимость.

Не предлагать снятие PeerFlood, сброс лимитов, подмену аккаунта или рассылку в обход правил.
